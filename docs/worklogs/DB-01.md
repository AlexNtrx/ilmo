## 7. Important Code Explanations

### Difficult Code

ส่วนนี้ยังไม่มี algorithm ที่ซับซ้อน จุดสำคัญคือ schema เป็นเพียง
คำอธิบายโครงสร้างที่ Prisma เข้าใจ ยังไม่ได้เปลี่ยน PostgreSQL จริง
เพราะ DB-01 ไม่อนุญาตให้สร้างหรือ apply migration

### Important TypeScript Syntax

DB-01 ไม่ได้แก้ TypeScript แต่ `prisma generate` สร้าง TypeScript types
จาก enum และ model เหล่านี้ไว้ใน directory ที่ Git ignore

### Next.js Server and Client Boundaries

DB-01 ไม่ได้เพิ่ม Next.js code จึงยังไม่มี Server Component, Client
Component, Route Handler หรือ Server Action boundary ใหม่

### Validation Boundaries

`prisma validate` ตรวจความถูกต้องของ schema เท่านั้น ไม่ได้พิสูจน์ว่า
migration หรือ constraint ทำงานจริงใน PostgreSQL

### Transaction Boundaries

DB-01 ยังไม่มี query หรือ transaction การสร้าง Issue แบบ atomic
จะถูกพัฒนาใน work item ภายหลังตาม approved architecture

### Why This Approach Was Chosen

แยก enums และ Location ออกเป็น work item เล็กเพื่อให้เจ้าของตรวจชื่อ
type, field, required/optional behavior และ default ได้ก่อนเพิ่ม relation
ที่ซับซ้อนใน DB-02 ถึง DB-04

### Important Rejected Alternatives

- Implementing all domain models together — rejected because the
  approved workflow requires small DB work items.
- Creating a migration now — rejected because migration belongs to
  DB-05 and was explicitly excluded.
- Adding String length or public-code normalization rules — rejected
  because they are not approved for DB-01.

## 9. Problems Encountered

### Errors

- PowerShell execution policy blocked `npx.ps1`.
- PowerShell execution policy blocked `npm.ps1`.
- The first real build attempt could not reach Google Fonts inside the
  network sandbox.

### Unexpected Behavior

- Prisma format, validation, and generation succeeded through
  `npx.cmd`, despite the previously reported Windows engine limitation.

### Environment Limitations

- PowerShell script wrappers are disabled.
- A Next.js production build requires network access while the scaffold
  imports Google-hosted Geist fonts.
- Migration behavior remains untested.

### Workarounds

- Used `npx.cmd` and `npm.cmd`, which invoke the same installed tools
  without the blocked PowerShell wrappers.
- Retried the unchanged build command with approved network access.

### Verified Root Cause

The wrapper failures explicitly reported PowerShell execution-policy
errors. The first build explicitly reported failed Google Fonts
requests; the same build passed with network access.

### Remaining Uncertainty

- Whether Prisma migration commands can execute under the reported
  Windows schema-engine restriction
- Actual PostgreSQL migration behavior
- Future `publicCode` format and normalization rules
