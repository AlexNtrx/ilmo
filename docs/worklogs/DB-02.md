## 7. Important Code Explanations

### Difficult Code

`IssueCategory` เป็น model ที่กำหนดพฤติกรรมของหมวดหมู่ผ่าน field
หลายตัว แต่ DB-02 ยังไม่ได้สร้าง business logic จริง ค่า default
เพียงกำหนดค่าที่ Prisma Client ใช้เมื่อ caller ไม่ส่ง field นั้น

### Important TypeScript Syntax

DB-02 ไม่ได้แก้ TypeScript โดยตรง `prisma generate` สร้าง TypeScript
type สำหรับ `IssueCategory` และเชื่อม `mergeMode` กับ enum
`IssueMergeMode`

### Next.js Server and Client Boundaries

ไม่มี Next.js code เปลี่ยน จึงยังไม่มี Route Handler, Server Action,
Server Component หรือ Client Component boundary ใหม่

### Validation Boundaries

`prisma validate` ยืนยันโครงสร้าง schema และความสัมพันธ์กับ enum
แต่ไม่ได้ตรวจ business rules เช่นการจัดลำดับซ้ำหรือ combination ของ
`isUrgent` กับ `mergeMode`

### Transaction Boundaries

DB-02 ไม่มี query หรือ transaction เพราะยังไม่สร้าง application
behavior หรือแก้ PostgreSQL

### Why This Approach Was Chosen

การแยก IssueCategory เป็น work item เดี่ยวช่วยให้ตรวจ default,
required fields และ deferred behavior ได้ก่อนเพิ่ม Issue relation ใน
DB-03

### Important Rejected Alternatives

- Adding an Issue relation — rejected because it belongs to DB-03.
- Adding indexes or unique category names — rejected because those
  details remain open.
- Defaulting `sortOrder` to zero — rejected by the approved DB-02 plan.
- Adding seed logic — rejected because seed execution belongs to DB-05.
