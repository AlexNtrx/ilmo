## 7. Important Code Explanations

### Difficult Code

relation ใน Prisma ประกอบด้วย foreign-key field เช่น `locationId`
และ relation field เช่น `location` ส่วน reverse field `issues`
ทำให้ Prisma เดินความสัมพันธ์ย้อนกลับได้ แต่ยังไม่ได้สร้าง query หรือ
business logic ใด ๆ

### Important TypeScript Syntax

DB-03 ไม่แก้ TypeScript โดยตรง แต่ Prisma Client ที่ generate แล้วจะมี
types สำหรับ model, enum, nullable fields และ relation query inputs

### Next.js Server and Client Boundaries

ไม่มี Next.js code เปลี่ยน จึงยังไม่มี server/client boundary ใหม่

### Validation Boundaries

`@db.VarChar(200)` บังคับขนาด description ใน PostgreSQL schema
ภายหลัง แต่ `prisma validate` ตอนนี้ยืนยันเพียงว่า declaration ถูกต้อง
ยังไม่ได้ทดสอบฐานข้อมูลจริง

### Transaction Boundaries

DB-03 สร้างโครงสร้างข้อมูลเท่านั้น การสร้าง Issue กับ confirmation
แบบ atomic ยังถูก deferred ไปยัง business service ใน vertical slice

### Why This Approach Was Chosen

ใช้ `Restrict` เพื่อรักษาข้อมูลที่ถูกอ้างอิง และแยก indexes,
one-open invariant, history และ transactions ออกตาม approved work-item
boundaries

### Important Rejected Alternatives

- Adding indexes or a partial unique constraint — deferred.
- Making `sourceHash` required or unique — privacy design is open.
- Cascading deletion of confirmations — conflicts with approved
  preservation direction for this work item.
- Adding history or Better Auth models — belongs to DB-04.
